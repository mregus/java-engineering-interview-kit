# M3 — Transaction atomicity

**Planned for V0.2 · Mid-level · about 15 minutes**

The ordinary V0.1 transaction/audit creation is atomic. A later isolated exercise variant will deliberately allow the financial write to commit before audit failure. That defective variant and its exercise test task are not supplied yet.

Repair the variant so financial and audit writes succeed or roll back together. Prove a successful pair and an injected audit failure using an integration test that crosses the actual service transaction boundary. Explain propagation, rollback rules, and persistence timing. No reference solution is included in V0.1.
