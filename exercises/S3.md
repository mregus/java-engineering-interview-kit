# S3 — Reporting period locking

**Planned for V0.3 · Senior · about 30 minutes, or implementation plus discussion**

Introduce a ReportingPeriod with client, fund, inclusive start/end dates and OPEN/CLOSED status. Reject reversed ranges and overlapping closed periods for the same fund. Closed periods reject create/update/delete financial writes. Updates must check both old and proposed date/fund. Reopening restores writes. Coordinate closing with concurrent financial writes.

Explain auditability, transaction boundaries, database concurrency protection, and evolution across services. Use PostgreSQL tests for contested operations; a distributed system is unnecessary. V0.1 contains no ReportingPeriod entity, locking implementation, financial update/delete API, or S3 exercise task.
