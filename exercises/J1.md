# J1 — Fix financial balance calculation

**Implemented exercise · Junior · about 10 minutes**

`src/main/java/com/interview/ledger/service/BalanceService.java` contains an existing calculation that incorrectly adds every positive stored amount. Fix this method. It is deliberately independent of persistence and the reporting endpoint.

Contributions and interest income increase the balance. Distributions, general expenses, and management fees decrease it. Use `BigDecimal` throughout; the enum provides direction. An empty list returns `0.00`. Negative balances are valid. Inputs are non-null lists containing valid persisted transaction objects; null-policy expansion is outside this exercise.

| Scenario | Expected balance |
|---|---:|
| Empty list | 0.00 |
| Contribution 1000.00 | 1000.00 |
| Contribution 1000.00, distribution 200.00 | 800.00 |
| General expense 50.00 | -50.00 |
| Contribution 1000.00, interest 0.30, distribution 200.00, expense 0.10, management fee 25.00 | 775.20 |

Add or improve unit tests and explain how your implementation handles all five types without changing stored signs. Streams and iteration are both acceptable. Avoid float/double conversion and avoid changing other exercises.

```bash
./gradlew exerciseJ1
./gradlew test
```

Public tests are `src/exerciseTest/java/com/interview/ledger/exercises/J1BalanceTest.java`. The starter passes two cases and fails three. Assessment covers collections, enums, decimal correctness, debugging, and test reasoning. No balance REST endpoint is required.
