# M2 — Fund financial reporting

**Implemented exercise · Mid-level · about 20 minutes**

Implement `ReportingService.report` for:

```http
GET /api/clients/1/funds/1/report?from=2026-03-01&to=2026-03-31
```

A valid request currently returns an explicit 501 exercise response. `LedgerService` already checks the client's fund ownership and date ordering. Use the repositories or extend them with appropriate queries. **Do not depend on J1's BalanceService**: this exercise must work while J1 remains defective.

Return the existing `FundReport` DTO with `fundId`, `from`, `to`, `openingBalance`, `totalCredits`, `totalDebits`, `netMovement`, and `closingBalance`.

- Opening balance includes signed transactions strictly before `from`.
- Period credits and debits include transactions on both boundary dates.
- Net movement = period credits − period debits.
- Closing balance = opening balance + net movement.
- Exclude all transactions after `to`; keep every query scoped to client and fund.
- Both dates are required. Reversed ranges return 400. Unknown or cross-client funds return 404.
- A valid fund with no transactions returns zero totals. Negative totals for net movement or balance are permitted.
- Preserve decimal precision with `BigDecimal`. Use USD, the sole supported currency.

[DATABASE.md](../docs/DATABASE.md) lists the exact dedicated Growth Fund fixture. Its March result is:

```json
{
  "fundId": 1,
  "from": "2026-03-01",
  "to": "2026-03-31",
  "openingBalance": 1000.00,
  "totalCredits": 550.00,
  "totalDebits": 225.00,
  "netMovement": 325.00,
  "closingBalance": 1325.00
}
```

Income Fund (client 1, fund 2) has a valid participation but no transactions. A one-day Growth Fund range on March 15 must include that day's distribution, exclude later fees/contributions, and carry earlier activity into opening balance.

Prefer database-side aggregation for scalable work. A correct in-memory implementation can demonstrate partial competency; explain its memory and query cost. Add boundary, empty, and tenant-scoping tests. Do not edit the fixed fixture or hardcode expected totals.
