# J2 — Investor request validation

**Implemented exercise · Junior · about 10 minutes**

Improve `POST /api/clients/{clientId}/investors`. The starter has incomplete validation, accepts blank names and malformed emails, and returns 200 without a Location header after successful creation.

Requirements:

- Name and email are required. Names cannot be blank; email must be a valid email address and nonblank.
- Invalid requests return HTTP 400 with a ProblemDetail response and persist no investor record.
- Successful creation returns HTTP 201 and a Location pointing to the created investor's GET resource.
- Duplicate normalized email within the same client returns 409. Existing case-insensitive normalization and client scoping must remain intact.
- Missing and cross-client resources retain 404 behavior. Existing size limits still apply.

Start with `dto/ApiModels.java` (`CreateInvestorRequest`), `controller/InvestorController.java`, and the centralized error handler. Constructor injection and ordinary Bean Validation are available. The baseline service's null guard protects required columns but is incomplete input validation. The public valid example uses an ordinary valid email; leading/trailing whitespace is normalized in the service and is not required to be accepted by new email-format validation.

Acceptance scenarios: valid investor; missing name; blank name; missing email; invalid or blank email; duplicate investor within a client. Add meaningful MockMvc tests, including a row-count check for rejected input. Baseline tests intentionally allow either successful 2xx status so correcting J2 will preserve the baseline.

```bash
./gradlew exerciseJ2
./gradlew test
```

Public tests: `src/exerciseTest/java/com/interview/ledger/exercises/J2InvestorValidationTest.java`. Some missing-field/duplicate cases already work; the full contract does not. Assessment covers Spring MVC, DTO validation, HTTP semantics, errors, and persistence side effects.
